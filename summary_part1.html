1. Application Security 🛡️

1.1 Software Vulnerabilities

  • Buffer Overflow — เขียนข้อมูลเกินขนาด buffer → รัน arbitrary code ได้
  • Integer Overflow — ค่าเกิน range (เช่น 255+1=0 ใน unsigned char) → crash/exploit
  • Null Pointer Dereferencing — อ่าน/เขียน memory location ที่เป็น null → crash
  • Race Condition — ผลลัพธ์ขึ้นกับ timing ของ events; TOCTTOU = Time of Check/Time of Use
  • Memory Leak — allocate memory แต่ไม่ release → host หมด memory
  • Resource Exhaustion — CPU, memory, disk, network ถูกใช้จนหมด
  • DLL Injection — บังคับ process โหลด malicious DLL
  • Pass the Hash — ใช้ NTLM hash จาก memory โดยไม่ต้อง crack password → lateral movement

1.2 Web Application Attacks

  • URL Analysis — HTTP methods: GET, POST, PUT, HEAD; Percent encoding
  • API Attacks — ต้องใช้ HTTPS เสมอ; จุดอ่อน: secrets mgmt, input validation, error info leak
  • Replay Attack — resubmit authorization token/cookie
  • Session Hijacking — ขโมย cookie; CSRF/XSRF = ส่ง URL ไปเว็บที่ user login อยู่
  • Clickjacking — ซ้อน invisible layer ดักจับ click
  • SSL Strip — exploit HTTP→HTTPS redirect; แก้ด้วย HSTS
  • XSS (Cross-Site Scripting):
    • Reflected (Non-persistent) — script อยู่ใน link
    • Stored (Persistent) — script ถูกเก็บใน database
    • DOM-based — client-side script
  • SQL Injection — ใส่ SQL ผ่าน input เช่น ' or 1=1--#
  • Directory Traversal — ../../etc/config เข้าถึงไฟล์นอก root
  • Command Injection — ทำให้ server รัน OS shell command
  • SSRF — ทำให้ server ส่ง request ไปยัง internal service

1.3 Secure Coding Practices

  • OWASP — แนวทาง security best practice
  • Input Validation — ตรวจสอบทุก input จาก user/API
  • Output Encoding — strip illegal chars, normalize
  • Client-side vs Server-side Validation — ใช้ทั้งคู่; client ไม่น่าเชื่อถือ 100%
  • Secure Cookies — ใช้ Secure, HttpOnly, SameSite attributes
  • Response Headers — HSTS, CSP, Cache-Control
  • Error Handling — SEH ป้องกัน info leak; ไม่แสดง default error messages
  • Static Analysis — วิเคราะห์ source code ด้วย automated tool
  • Dynamic Analysis — ทดสอบ runtime; fuzzing & stress testing

2. Data Privacy & Protection 🔒

2.1 Privacy vs Security

  • Security = CIA (Confidentiality, Integrity, Availability)
  • Privacy = ปกป้อง personal data ตาม regulation + สิทธิ data subjects

2.2 Data Types

ประเภทคำอธิบาย
PIIPersonally Identifiable Information
PHIProtected Health Information
PIFIPersonally Identifiable Financial Info
IPIntellectual Property

2.3 Data Roles

  • Data Owner — รับผิดชอบสูงสุด
  • Data Steward — ดูแล data quality
  • Data Custodian — จัดการ IT systems
  • DPO — ดูแล PII; Data Controller vs Data Processor

2.4 Data Classifications

  • Public → Confidential → Critical (Top Secret)
  • Proprietary = ข้อมูลที่มีมูลค่าเชิงพาณิชย์
  • Private/Personal = ระบุตัวบุคคลได้
  • Sensitive = ข้อมูลพิเศษ เช่น เชื้อชาติ ศาสนา

2.5 GDPR & PDPA

  • GDPR — กฎหมายคุ้มครองข้อมูลของ EU; สิทธิ data subjects, privacy notices, impact assessments
  • PDPA (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ.2562) — กฎหมายไทย
  • Data Sovereignty — กฎหมายขึ้นกับ jurisdiction ที่เก็บข้อมูล
  • Breach → ผลกระทบ: reputation damage, identity theft, fines → ต้อง notify

2.6 Data Protection Controls

2.7 DLP & Privacy Tech

  • DLP — scan files, ป้องกัน unauthorized copy; ใช้ policy server + endpoint/network agents
  • Remediation: Alert → Block → Quarantine → Tombstone
  • Data Minimization — เก็บเท่าที่จำเป็น
  • Deidentification — ลบ personal info จาก dataset
  • Anonymization — ลบถาวร ไม่สามารถย้อนกลับ
  • Pseudo-anonymization — ย้อนกลับได้ถ้ามี separate data source
  • Data Masking — redaction (irreversible)
  • Tokenization — แทนค่าด้วย random token, เก็บใน vault (reversible)

3. Firmware & Host Security 🖥️

3.1 Hardware Root of Trust

  • TPM (Trusted Platform Module) — chip บน motherboard เก็บ crypto keys; endorsement key
  • HSM (Hardware Security Module) — อุปกรณ์จัดการ digital keys, encryption/decryption
  • ทั้ง TPM/HSM มี unique private key ที่ burned ลง hardware

3.2 Boot Integrity

  • UEFI แทน BIOS แบบเก่า
  • Secure Boot — validate digital signatures ก่อนรัน boot loader/OS
  • Measured Boot — ใช้ TPM วัด hash ของ boot files แต่ละ stage
  • Remote Attestation — ส่ง boot info ไป verify ที่ remote system

3.3 Drive & USB Security

  • FDE (Full Disk Encryption) — เข้ารหัสทั้ง disk; key เก็บใน TPM
  • SED (Self-Encrypting Drive) — DEK/MEK + AK/KEK; Opal spec
  • BadUSB — malicious firmware ใน USB; ใช้ Sheep Dip (sandbox) ทดสอบ

3.4 Supply Chain & Vendor

  • ตรวจสอบ backdoor ใน hardware/firmware จาก supply chain
  • Vendor Assessment: viability, support, lock-in/lock-out, source code escrow
  • EOL = ไม่ขายแล้ว; EOSL = ไม่ support แล้ว
  • Agreements: MOU, BPA, NDA, SLA

3.5 Endpoint Hardening

  • ลด attack surface: ปิด interfaces/services/ports ที่ไม่ใช้
  • Configuration Baseline — template + GPOs + registry settings
  • Patch Management — update OS/app/firmware เป็นประจำ
  • Change Management — document + review ก่อน implement

3.6 Endpoint Protection

  • AV/Anti-malware — signature-based detection
  • HIDS/HIPS — file integrity monitoring + log/network scanning
  • EPP — รวม AV + HIDS + firewall + DLP ไว้ด้วยกัน
  • EDR — real-time visibility + behavior analytics + ML
  • Whitelisting — อนุญาตเฉพาะ app ที่อยู่ใน list
  • Blacklisting — บล็อก app ที่อยู่ใน list

3.7 Virtualization & Cloud

  • Type I Hypervisor (Bare Metal) vs Type II (Host-based)
  • Container — OS-level isolation (Docker); ไม่สามารถรัน OS ต่างกัน
  • VDI — Virtual Desktop Infrastructure; ใช้ thin client
  • VM Escape — code หลุดจาก VM ไป interact กับ hypervisor
  • Cloud: IaaS (infra) → PaaS (platform) → SaaS (software)
  • Shared Responsibility Model — แบ่งความรับผิดชอบระหว่าง CSP กับ customer
  • MSSP — Managed Security Services Provider

4. Network Security 🌐

4.1 Network Devices & ACLs

  • Switch Security — DHCP snooping, DAI, port security, MAC filtering
  • ACL — rules กำหนด allow/deny; จบด้วย implicit deny
  • Router ACL — filter ตาม IP, port, protocol

4.2 Firewalls

TypeDetail
Statelessใช้ ACL; Permission+Protocol+Src+Dst+Port
Statefulตรวจ state ของ session (established TCP)
NGFWApplication-aware + user-based + IPS + cloud inspection
UTMรวม firewall+AV+IPS+spam+DLP+VPN
WAFป้องกัน web application โดยเฉพาะ

4.3 Proxy, IDS/IPS

  • Forward Proxy — เปิด connection แทน internal client; Reverse Proxy — แทน external client
  • IDS — passive detection + logging/alerting
  • IPS — active response: reset session, apply filter, throttle bandwidth
  • Packet Sniffer — เช่น Wireshark; capture & analyze network traffic

4.4 Network Design & Zones

  • Network Segmentation — physical isolation, VLANs
  • Zones: Intranet (private), Extranet, Internet (public)
  • DMZ — แยก hosts ที่ต้อง Internet-facing (DNS, FTP, Mail, Web servers)
  • Topologies: Screened Subnet (dual firewall) vs Triple-Homed (single firewall)
  • Honeypot/Honeynet — ล่อ attacker เพื่อสังเกต methodology

4.5 VPN & Remote Access

  • TLS Tunneling — ผ่าน NAT ได้; SSTP ใช้ port 443
  • IPSec: AH (auth+integrity, protocol 51) + ESP (encryption, protocol 50)
  • Transport Mode — host-to-host (private network)
  • Tunnel Mode — gateway-to-gateway (เข้ารหัสทั้งหมด); ใช้ IKE port 500
  • Split Tunnel — encrypt เฉพาะ traffic ไป private network
  • Full Tunnel — encrypt ทุก traffic
  • NAC — posture assessment ตรวจ health ของ endpoint ก่อนอนุญาตเข้า network

4.6 Network Attacks

  • DoS — จาก 1 system; DDoS — จากหลาย systems
  • SYN Flood — disrupt TCP 3-way handshake (ไม่ส่ง ACK กลับ)
  • DRDoS — spoof victim IP → servers ส่ง SYN/ACK ไปหา victim
  • Spoofing — ปลอมแปลง MAC/IP; MitM attack
  • ARP Poisoning — ปลอม ARP reply → on-path attack
  • DNS Poisoning — corrupt DNS data → redirect traffic
  • Pharming — redirect web traffic; Domain Hijacking — เปลี่ยน registration
  • Replay Attack — capture data แล้วส่งซ้ำ เพื่อ impersonate
